# consult_message

## Purpose
One turn in a consult thread: a pathologist's question, or the agent's answer with the cases it cited, the pathologists it ranked and the steps it took.

## Fields

| Field | Type | Null | Description |
| --- | --- | --- | --- |
| `id` | `uuid` PK | no | Generated by the database. |
| `thread_id` | `uuid` FK | no | |
| `role` | `text` | no | `user` or `assistant`. |
| `content` | `text` | no | Markdown. In assistant messages, citations appear inline as `[case:<case_id>]`. |
| `attachments` | `jsonb` | yes | User messages only: `{region: {slide_id, x, y, width, height}}` and/or `{case_ids: [...]}` (F-07.9). |
| `citations` | `jsonb` | yes | Assistant only. List of `{case_id, slide_id?, patch_id?, quote?}` for every case cited (F-07.6). |
| `ranking` | `jsonb` | yes | Assistant only, when a consult recommendation was made. List of `{pathologist_id, name, specialty, case_count, case_ids}`, ordered (F-07.4). |
| `tool_trace` | `jsonb` | yes | Assistant only. List of `{tool, input, summary, duration_ms}` in call order (F-07.10). |
| `model` | `text` | yes | Model that produced the answer. |
| `input_tokens` | `integer` | yes | For tracking the credit budget. |
| `output_tokens` | `integer` | yes | |
| `status` | `text` | no | `complete`, `streaming` or `error`. |
| `created_at` | `timestamptz` | no | |

## Relationships
- `thread_id` → `consult_thread.id`.

## Indexes
- `(thread_id, created_at)` — load a thread in order.

## Rules
1. `ranking` is copied from the `rank_pathologists` tool result, not parsed from the model's text. Each entry's `case_count` equals the length of its `case_ids` (F-07.5).
2. Every case ID in `citations` and `ranking` was returned by a tool in the same turn. An ID the model produced that no tool returned is dropped before saving.
3. No case in `citations` is the thread's own case, an open case, or a held-out case. Signed-out prior cases of the *same* patient may be cited (and are marked `same_patient: true` through their `CaseSummary`).
4. The assistant row is inserted as `streaming` when the turn starts and updated to `complete` or `error` when it ends.

## Source
User messages come from the consult panel. Assistant messages are written by the agent loop.

## API shape
`ConsultMessage` — `id`, `role`, `content`, `attachments`, `citations` (each expanded with a `CaseSummary`), `ranking`, `tool_trace` (without `input`), `status`, `created_at`.

Never sent: `input_tokens`, `output_tokens`, and tool inputs.
