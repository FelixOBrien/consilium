# ingestion_job

## Purpose
A request to ingest one slide, and the record of its progress. The table is the queue between the app and the GPU worker ([architecture D12](../architecture.md#decisions)).

## Fields

| Field | Type | Null | Description |
| --- | --- | --- | --- |
| `id` | `uuid` PK | no | Generated by the database. |
| `dataset` | `text` | no | TCGA project ID, for example `TCGA-BRCA`. |
| `slide_path` | `text` | no | GDC diagnostic slide file name or file ID within that project. |
| `case_id` | `text` | yes | Set once the worker has resolved the case. |
| `slide_id` | `text` | yes | Set once the slide row exists. |
| `requested_by` | `text` FK | yes | The acting pathologist who queued it. |
| `status` | `text` | no | `queued`, `running`, `done` or `failed`. |
| `stage` | `text` | yes | Current or last stage: `download`, `segment`, `embed`, `project`, `thumbnails`, `reports`, `load`, `index`. Null while queued. |
| `stage_history` | `jsonb` | no | List of `{stage, started_at, finished_at, detail}`. Empty when queued. |
| `counts` | `jsonb` | yes | `{patches, chunks}` once known (F-09.13). |
| `error` | `text` | yes | Message when failed. |
| `attempts` | `integer` | no | Number of times a worker has started it. |
| `worker_id` | `text` | yes | Which worker holds it. |
| `created_at` | `timestamptz` | no | |
| `started_at` | `timestamptz` | yes | |
| `finished_at` | `timestamptz` | yes | |

## Relationships
- `requested_by` → `pathologist.id`. `case_id` and `slide_id` are plain values, not foreign keys, because the rows may not exist yet.

## Indexes
- `(status, created_at)` — the worker's next-job query and the jobs list.
- Unique `(dataset, slide_path)` where `status in ('queued', 'running')` — no duplicate active jobs.

## Rules
1. A worker claims the oldest queued job in one statement that locks the row and skips rows locked by another worker, setting `status = 'running'`, `worker_id`, `started_at` and incrementing `attempts`.
2. The worker updates `stage` and appends to `stage_history` as each stage starts and finishes.
3. On success: `status = 'done'`, `finished_at` set, and the slide's `status` is `ready`. On failure: `status = 'failed'` with `error` and the failing `stage`.
4. Retrying a failed job sets it back to `queued` and keeps its history.
5. A job for a slide that is already `ready` finishes as `done` immediately without repeating work.

## Source
Created from the ingestion screen ([S-08](../screens/S08-ingestion.md)). Updated only by the worker.

## API shape
`IngestionJob` — all fields except `worker_id`, with `requested_by` as `PathologistRef`. `outcome` is not stored. It is set only on `POST /api/ingestion/jobs`: `created` (HTTP 201, a new queued job), `retried` (the latest failed job is queued again and keeps `stage_history` and `attempts`), `duplicate_active` (the existing queued or running job), or `already_ingested` (the slide is already `ready`, so the job is `done` with `case_id`, `slide_id`, and `{patches, chunks}` from Postgres). The other three outcomes are HTTP 200. Later reads leave `outcome` null.

`IngestionJobCreate` — `dataset`, `slide_path`.

`GET /api/health` adds `cases`, `slides`, `patches`, and `report_chunks` (counts of `path_case`, `slide`, `patch`, and `report_chunk`) when Postgres is reachable. `status` stays `ok`.
